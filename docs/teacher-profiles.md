# 教师资料同步

在后台“课程数据 → 教师资料与重名”点击“批量同步教师资料”。采集器读取长安大学[教师主页站](https://js.chd.edu.cn/)公开目录，再获取与本站教师姓名和学院对应的主页。无需学校登录或外部 SDK，Go 采集器随 API 一同打包。后台显示目录页数、详细资料进度和读取失败数量；取消或目录获取失败不会保存不完整目录。

只有双方均唯一的“姓名＋学院”才自动关联。不模糊匹配姓名，不自动将不同学院当成同一学院。仅忽略空白和中英文括号差异。教师主页地址用于区分候选资料，不代替本站教师编号或教务身份。同学院同名时进入“重名特别处理”，管理员比较学校履历、研究方向和本站任课记录后确认；无法确认时保持待处理。人工确认在后续同步中保留，但候选主页消失或姓名、学院发生变化时需重新确认。

教师列表不显示空职称。详情页仅展示职称、学位、联系方式、办公地点、研究方向及最多 300 字的简介，其他内容通过“前往教师主页”查看；详情页缺失项显示“暂无数据”。PC 左侧为教师资料，右侧为课程，窄屏上下排列。联系方式来自学校主页公开的办公电话和邮箱，不采集登录凭据。

完整目录成功后，在同一个数据库事务中保存匹配结果。个别主页请求或模板解析失败会报告失败数量，目录姓名和职称仍可用于匹配，之前已读取的详细字段保留。最多 3 个并发 HTTP 请求，每个请求 25 秒，临时网络失败最多重试两次，整个任务 20 分钟到期。API 重启会结束活动任务；重新同步即可，不需要持续保存学校登录态。

部署先应用 `0019_teacher_profiles.up.sql`，再更新 API。新增表保存公开主页资料，教师表新增资料、候选和确认状态；不改动教务教师身份、教学班或已有点评。同步不会替代全校开课同步，新导入教师可通过再次同步补充资料。

管理接口均要求管理员权限：`GET /api/admin/teacher-profiles` 查询进度，`POST /sync` 开始同步，`POST /cancel` 取消，`GET /matches` 查询重名候选，`PUT /:teacherID` 确认候选（请求体为 `{"url":"学校主页地址"}`）。只能选择该教师当前候选列表中的主页，不能任意填入其他学院或站外地址。

## 手动维护

“教师资料”主界面按姓名、学院、职称筛选并分页展示本站教师。点击“编辑”可维护姓名、学院、职称、学位、联系方式、办公地点、研究方向、个人简介与教师主页链接；无需学校主页存在或先同步。姓名、学院必填，其余允许留空。修改沿用原教师 ID，因此原任课和点评关联保留。

手动保存后整份展示资料由本站维护，不再被教师主页同步或开课同步覆盖（包括刻意留空的字段）。自动同步仍更新来源候选资料，方便核对重名；确认候选不会覆盖已手动保存的展示资料。同步进行中暂不可编辑，避免并发覆盖。

自动填充和重名处理放在主界面下方的折叠区。部署同时应用 `0020_teacher_profile_overrides.up.sql`。新增 `GET /teachers` 支持分页与筛选，`PUT /:teacherID/details` 保存展示资料；均沿用管理员权限校验。教师主页链接允许管理员填写 HTTP/HTTPS 地址，只供用户主动打开，不由采集器请求任意地址。

## 单教师填充

批量同步仍在表格外的折叠区，负责全局教师。编辑弹窗中的“获取并填入资料”根据当前姓名与学院查询教师主页，只读取这位教师的详情。无需先完成批量同步。唯一匹配时直接填入，多位同学院同名教师需先查看学校主页再选择。未匹配、连接失败时保留表单原内容；读取成功只替换有内容的资料字段，来源缺失的字段保留现有值。姓名与学院不被自动改写。核对并点击“保存资料”后才写入数据库，关闭弹窗则放弃填充。新接口 `POST /:teacherID/preview` 为只读预览，不启动全局任务，不修改其他教师或重名关联。
