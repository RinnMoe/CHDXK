# 我的课程导入

“我的课程”的“选课记录”支持两种入口：

- **教务扫码导入**：已实现。登录本站后点击“导入我的课程”，用微信扫描学校登录二维码并确认，勾选学期，点击“导入所选学期”。导入完成后自动刷新选课记录。
- **MyCHU 应用导入**：仅预留入口，按钮不可用；目前没有上传接口、应用授权或客户端实现。

## 用户与普通管理员

导入读取的是扫码账号的个人课表，只增加当前本站账号的选课记录，不修改学校教务数据或全校开课数据。课程以学期和课程序号匹配本站教学班；重复导入不会生成重复记录。若课表只有教务内部教学班编号，使用编号与课程名称共同匹配。无法唯一匹配的课程会显示在“暂未匹配”清单中，不会随意关联到同名课程或某位教师。

遇到未匹配课程时，管理员先在“开课记录”中同步对应学期的数据，用户再扫码导入。空课表不会删除已有记录，已完成学期在后续学期失败或任务取消时仍然保留。导入完成、取消或超时后释放本次登录连接；下次导入重新扫码，不保存教务登录态。初始管理员也可以使用自己的学校账号扫码，个人课程导入不依赖积分账户或 ResHub 绑定状态。

## 技术管理员

复用 Docker 内置采集器与 CAS/微信扫码实现，不需要外部 SDK 目录。采集器通过 `--personal` 进入个人课表模式，使用 EAMS 首页菜单加载课表查询片段，并调用查询页自己的只读 `searchTable()`，读取 `table0.activities`。课表活动按教学班去重，教师顺序不参与匹配。个人模式不运行全校课程详情采集，也不生成课程 ZIP。

认证接口：

- `POST /api/course/enrollment-sync` 创建任务。
- `GET /api/course/enrollment-sync/:jobID` 查询二维码、状态及逐学期结果。
- `POST /api/course/enrollment-sync/:jobID/run`，请求体 `{"semesters":["2026-2027-1"]}`。
- `POST /api/course/enrollment-sync/:jobID/cancel` 取消当前用户任务。

用户 ID 从本站会话取得，不接受客户端指定导入目标。任务只对创建者可见；同一用户最多一个活动任务，单个 API 进程最多 4 个个人导入任务，每个任务 15 分钟到期，结果仅短期保存在进程内。API 重启后重新扫码。多实例部署需要将任务请求固定到同一实例；此版本尚未提供跨实例调度。

导入按完整学期事务提交，使用现有 `(user_id, course_id, semester)` 唯一约束保证幂等；不新增数据库表，也不替换管理员导入的课程与教学班。新记录保存后清除用户选课查询缓存。

MyCHU 后续应复用同一匹配与写入逻辑，并在确认原生应用登录契约后单独接入；本次没有开放接受任意课表 JSON 的公共写入路径。

## 验证说明

后端测试覆盖账号隔离、活动任务上限、完整学期校验、跨学期匹配、模糊匹配拒绝与重复导入。采集器浏览器回归使用拦截请求的 EAMS 页面，覆盖折叠菜单、延迟加载的学期日历和连续学期读取；不使用真实学校账号。安装 Chromium 后可设置 `BKJW_BROWSER_TESTS=1` 并运行采集器 `pnpm test`；必要时同时设置 `PLAYWRIGHT_BROWSERS_PATH` 为本项目浏览器运行时目录。

首次真实扫码验证完成了学校登录，但个人课表初始化失败；随后已调整菜单加载及等待逻辑，模拟浏览器回归通过。真实个人课表读取、匹配及写入仍需再次扫码确认，尚不能以静态或模拟测试替代该项验证。
