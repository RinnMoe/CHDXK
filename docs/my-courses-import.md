# 我的课程导入

“我的课程”的“选课记录”支持两种入口：

- **教务扫码导入**：已实现。登录本站后点击“导入课程”，在“教务扫码”中用微信扫描学校登录二维码并确认，点击“导入全部学期”。逐个读取全部可用学期，导入完成后自动刷新选课记录。
- **MyCHU 应用导入**：仅预留入口，按钮不可用；目前没有上传接口、应用授权或客户端实现。

## 用户与普通管理员

“导入课程”弹窗将“教务扫码”“手动添加”和预留的“MyCHU”放在同一入口内。“手动添加”可以搜索本站已收录课程，选择已有学期和教学班后保存。每条选课记录旁的编辑按钮使用相同选择流程。无法填写未收录课程或任意学期；教学班如被管理员删除，保存时会提示重新选择。同一课程在同一学期只保留一条选课记录。

扫码后先在手机确认登录。页面依次显示“手机已确认，正在连接本科教务”和“教务登录成功，正在读取学期列表”，并标记扫码确认、连接教务、读取学期三个步骤的进度。手机确认后二维码自动收起，无需再次扫码；失败时显示原因并允许重新连接。管理员教务同步使用相同的登录反馈。

导入读取的是扫码账号的个人课表，只增加当前本站账号的选课记录，不修改学校教务数据或全校开课数据。课程以学期和课程序号匹配本站教学班；重复导入不会生成重复记录。若课表只有教务内部教学班编号，使用编号与课程名称共同匹配。无法唯一匹配的课程会显示在“暂未匹配”清单中，不会随意关联到同名课程或某位教师。

遇到未匹配课程时，管理员先在“开课记录”中同步对应学期的数据，用户再扫码导入。短暂的请求或课表加载失败会自动重试最多两次，页面显示当前重试次数，无需再次扫码。登录过期、无权访问或课表格式无法读取时停止导入并显示具体原因。空课表不会删除已有记录，已完成学期在后续学期失败或任务取消时仍然保留。导入完成、取消或超时后释放本次登录连接；下次导入重新扫码，不保存教务登录态。初始管理员也可以使用自己的学校账号扫码，个人课程导入不依赖积分账户或 ResHub 绑定状态。

## 技术管理员

复用 Docker 内置采集器与 CAS/微信扫码实现，不需要外部 SDK 目录。采集器通过 `--personal` 进入个人课表模式，使用 EAMS 首页菜单加载课表查询片段，并调用查询页自己的只读 `searchTable()`，读取 `table0.activities`。课表活动按教学班去重，教师顺序不参与匹配。个人模式不运行全校课程详情采集，也不生成课程 ZIP。

认证接口：

- `POST /api/course/enrollment-sync` 创建任务。
- `GET /api/course/enrollment-sync/:jobID` 查询二维码、状态及逐学期结果。
- `POST /api/course/enrollment-sync/:jobID/run`，请求体 `{"semesters":["2026-2027-1"]}`。
- `POST /api/course/enrollment-sync/:jobID/cancel` 取消当前用户任务。

用户 ID 从本站会话取得，不接受客户端指定导入目标。任务只对创建者可见；同一用户最多一个活动任务，管理员与个人导入共用容量为 128 的调度队列，单个 API 进程最多运行 64 个个人采集任务，管理员全校同步独占运行，每个任务 15 分钟到期，结果仅短期保存在进程内。API 重启后重新扫码。多实例部署需要将任务请求固定到同一实例；此版本尚未提供跨实例调度。

导入按完整学期事务提交，使用现有 `(user_id, course_id, semester)` 唯一约束保证幂等；不新增数据库表，也不替换管理员导入的课程与教学班。新记录保存后清除用户选课查询缓存。临时请求失败或课表加载失败会在 1 秒、2 秒后重试同一临时连接中的 HTTP 请求；每学期独立解析响应，避免旧数据残留。日志只记录任务编号、失败学期和白名单错误码，不记录学校登录凭据或跳转地址。

MyCHU 后续应复用同一匹配与写入逻辑，并在确认原生应用登录契约后单独接入；本次没有开放接受任意课表 JSON 的公共写入路径。

## 验证说明

Go 采集器回归覆盖扫码反馈、CAS Cookie 与自动提交表单、EAMS 登录验证、完整学期目录、个人和班级查询身份区分、连续学期与空课表、教学班去重、请求重试、取消、异常响应拒绝。后端应用测试继续覆盖账号隔离、排队、完整学期提交、匹配与重复导入。

2026-10-06 旧浏览器采集器曾实际扫码读取并导入个人课程；该结果不作为新 HTTP 采集器的实际登录验证。新版本本轮无人值守检查不需要扫码，仅真实获取二维码；实际扫码后全学期采集仍需后续验收。详见 [Go HTTP 采集器](http-course-collector.md)。
